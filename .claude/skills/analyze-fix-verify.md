# 分析-修复-验证流程

当遇到性能问题或异常时，按以下流程进行调试：

## 1. 分析问题

**收集数据：**
- 使用监控脚本/工具采集实时数据
- 记录关键指标（位置、速度、力矩、误差等）
- 确认问题现象和量化指标

**定位原因：**
- 检查控制参数（kp、kd、ki）
- 检查硬件限制（电压、电流、温度）
- 检查通信质量（丢包、延迟）
- 检查机械特性（摩擦、间隙、负载）

## 2. 修复问题

**参数调整原则：**
- 一次只改一个参数
- 小步迭代，避免大幅调整
- 记录每次修改的参数和效果

**常见调整策略：**
| 问题 | 调整方向 |
|------|----------|
| 稳态误差大 | 增大 kp |
| 响应慢 | 增大 kp，减小 kd |
| 振荡 | 减小 kp，增大 kd |
| 超调大 | 增大 kd |

## 3. 验证效果

**测试流程：**
1. 编译固件：`./scripts/flash.sh`
2. 监控数据：`./scripts/monitor_motor.sh`
3. 对比前后数据
4. 确认问题是否解决

**验证标准：**
- 误差是否在可接受范围内
- 响应速度是否满足要求
- 是否引入新问题

## 4. 记录归档

**记录内容：**
- 问题描述
- 根本原因
- 修改方案
- 测试结果
- 经验总结

**归档位置：**
- 项目文档：`~/Documents/obsidian/Project/{project_name}/`
- 文件名：`{问题类型}-解决方案.md`

## 示例：电机位置误差优化

```bash
# 1. 监控当前位置误差
./scripts/monitor_motor.sh 30

# 2. 分析数据，发现误差 10%
# 目标=30度, 实际=26.8度, 误差=3.2度

# 3. 调整参数（增大 kp）
# kp: 20 -> 50

# 4. 重新编译刷写
./scripts/flash.sh

# 5. 验证效果
./scripts/monitor_motor.sh 30
# 结果：误差降低到 2-5%

# 6. 记录经验
# kp=50 时位置误差可控制在 2% 以内
```

## 经验库

### 电机控制参数

| 电机型号 | kp | kd | 备注 |
|----------|-----|-----|------|
| Damiao 4340P | 50 | 5 | 非空载，误差约 2-5% |

### 常见问题

**非空载位置偏差：**
- 现象：实际位置与目标位置有 2-5% 误差
- 原因：电机负载导致需要更大维持力矩
- 解决：增大 kp 或添加前馈力矩补偿重力
- 注意：这是正常现象，非空载时无法完全消除
